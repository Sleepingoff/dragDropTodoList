1. 클래스: StatusManager
   역할: 상태와 관련된 데이터를 관리하고, 상태별 할 일 목록을 화면에 표시하거나 업데이트하는 역할을 담당합니다.
2. 주요 속성
   status: 상태 목록을 저장하는 배열.
   statusBtns: 상태 버튼 목록을 저장하는 배열.
   list: 상태별 할 일 리스트 DOM 요소를 저장하는 배열.
   todos: 전체 할 일 목록을 저장하는 배열.
3. 주요 메서드

`getToDos(todos)`

역할: 전달받은 할 일 목록(todos)을 저장하고, 상태별로 화면에 표시.
작동 방식: paintStatusList() 메서드를 호출하여 상태별 할 일 리스트를 갱신.

`updateStatus(status)`

역할: 새로운 상태를 추가.
작동 방식:
중복 상태를 방지하기 위해 기존 상태 목록을 확인.
새로운 상태를 status 배열에 추가하고, 상태 리스트를 생성.

`createStatusList(status)`

역할: 새로운 상태에 대한 리스트 DOM 요소를 생성하고 화면에 추가.
작동 방식:
상태 이름을 기반으로 <div>와 <ul> 요소를 생성.
생성된 리스트를 list 배열에 추가.

`paintStatus(status)`

역할: 새로운 상태 버튼을 화면에 표시.
작동 방식:
상태 이름을 기반으로 <button> 요소를 생성.
버튼 클릭 시 해당 상태를 삭제하도록 이벤트 리스너를 추가.

`paintStatusList()`

역할: 상태별로 할 일 리스트를 화면에 표시.
작동 방식:
기존 리스트를 초기화.
todos 배열을 순회하며 각 할 일을 해당 상태의 리스트에 추가.

`deleteStatus(status)`

역할: 특정 상태를 삭제.
작동 방식:
해당 상태의 할 일 상태를 초기화.
상태 목록, 버튼, 리스트에서 해당 상태를 제거.
화면을 갱신하여 남아 있는 상태를 다시 표시.

`deleteStatusList(status)`

역할: 특정 상태에 해당하는 리스트 DOM 요소를 삭제.
작동 방식:
section 내의 자식 요소를 순회하며, 해당 상태의 리스트를 제거.

## 문제점 분석 및 개선 사항

1. 중복 코드
   문제: paintStatus와 createStatusList 메서드가 상태별로 반복적으로 호출됩니다.
   개선 방안: 상태 목록을 순회하며 반복적으로 처리하도록 리팩토링.
2. DOM 조작 최적화
   문제: paintStatusList 메서드에서 리스트 초기화 시 while (list.firstChild)를 사용하여 DOM 요소를 반복적으로 제거.
   개선 방안: DOM 조작을 최소화하기 위해 리스트를 한 번에 초기화하거나, 가상 DOM을 활용.
3. 이벤트 리스너 중복
   문제: paintStatus 메서드에서 상태 버튼을 다시 그릴 때마다 이벤트 리스너가 중복으로 추가될 가능성이 있음.
   개선 방안: 기존 이벤트 리스너를 제거하거나, 이벤트 위임(Event Delegation)을 활용.
4. 상태 삭제 시 데이터 동기화 문제
   문제: deleteStatus 메서드에서 상태를 삭제한 후, todos 배열과 status 배열 간 동기화가 명확하지 않음.
   개선 방안: 상태 삭제 후 todos 배열을 필터링하여 불필요한 데이터를 제거.
5. Magic String 사용
   문제: "archive", "progress", "done" 등 문자열이 여러 곳에서 반복적으로 사용됨.
   개선 방안: 상수로 정의하여 재사용성을 높임.
6. 테스트 및 에러 처리 부족
   문제: 메서드 호출 시 에러 처리가 부족하며, 예상치 못한 입력값에 대한 방어 코드가 없음.
   개선 방안: 입력값 검증 및 에러 처리를 추가.
